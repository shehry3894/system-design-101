Four trips happen before the page arrives: DNS, TCP, TLS, HTTP

You type google.com. The browser finds the address, connects, secures the line, then asks. Use Prev / Next or the arrow keys.

IP = Internet Protocol · NAT = Network Address Translation · DNS = Domain Name System · TLD = top-level domain · TTL = time to live · TCP = Transmission Control Protocol · TLS = Transport Layer Security · HTTP = Hypertext Transfer Protocol

  1. Your laptop has a private address. The router’s NAT swaps it for one public address.
  2. The browser needs an IP for google.com. The OS stub resolver asks a recursive resolver.
  3. Cache miss: the resolver asks the root, then the .com TLD, then Google’s DNS server.
  4. Google’s server returns the IP with a TTL. The resolver caches it for that many seconds.
  5. The browser opens TCP to port 443 in three packets: SYN, SYN-ACK, ACK.
  6. TLS 1.3 agrees on keys and checks the certificate in one round trip.
  7. The browser sends GET / with a Host: google.com header.
  8. The IP belongs to a gateway. It forwards the request to one of many servers.
  9. The response returns the same way. NAT hands it back to 192.168.1.20.

Solid arrows are requests; dashed arrows are replies. The current step is bold and thick; earlier steps are faded. Addresses are examples.
